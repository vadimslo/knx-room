3.2 Validator scoring functions for each live workload class

Tier 1 Filed, partial

In preparation. Per-workload scoring functions with weights and thresholds for drone navigation, robot-arm VLA and SLAM; values of the metascore coefficients.

Scoring on Konnex happens at two levels. Subnet validators score miner work against the task instruction for each workload class (drone navigation, roboarm VLA, SLAM), and the chain scores the validators themselves with a metascore S = αC + βH - γP that rewards agreement with the validator set, accuracy on hidden reference tasks, and clean operation. Inside each validator a VLA or LLM layer and a deterministic layer must agree before a vote is published; if they conflict the validator abstains.

Validator metascore

The chain combines three signals into one scalar per validator, written S(Vi) for validator i:

S(Vi) = α · C(Wi, W̄) + β · H(Vi) - γ · Pi

TermMeaningHow it is produced
C(Wi, W̄)Consensus alignment: similarity between validator i's weight vector Wi over a batch of miners or tasks and the network aggregate W̄The chain builds W̄ with a governance-tunable rule (median per dimension or a stake-weighted blend); C is a similarity such as cosine mapped to the interval 0 to 1. Systematic drift from W̄ lowers validator trust and effective yield. Pseudorandom hidden spot checks make blind copying of consensus risky.
H(Vi)Honeypot accuracy: share or count of hidden reference tasks where validator i's grades match the known-good labelsThe network or a governed oracle injects reference runs whose correct grades are known before validators vote (deterministic simulators such as ManiSkill, Isaac Sim or subnet benches). Validators do not know which jobs are honeypots. Awarding a high score to an objectively failed reference draws a hard penalty up to slashing on governance-defined severity tiers.
PiOperational penaltiesHigh latency, missed voting epochs, broken commitments and similar slashing-adjacent behaviour.
α, β, γPositive governance weightsSet how much each term moves S; tuned per subnet phase and mainnet rollout.

The metascore does not replace workload-specific scoring: miner rewards and PoPW acceptance still flow from subnet verifiers and task semantics. The metascore governs which validators are trusted to emit those scores and at what economic weight.

Two-tier validation inside the validator node

Each validator's local pipeline is designed as two independent channels that must agree before a vote is safe to publish.

ChannelQuestion answeredTypical checks
VLA or LLM layerDid the miner follow the instruction semantically?Vision-language model or LLM judgement of task match, safety, efficiency and coherence from frames and traces
Deterministic layerAre the physical constraints satisfied?Torque limits, timing windows, joint limits, replay deltas against simulator logs, closed-form KPI checks

Abstention rule: if the two layers conflict, the validator abstains or requests an extended check along a subnet-defined escalation path. Publishing a confident vote despite internal disagreement is scored against the validator under the consensus and honeypot terms.

The public reference validator for drone navigation

The published drone subnet repository contains the validator scoring that runs on testnet. Each validator round is a single-step query: the validator teleports to a random spot in the Unreal Engine environment, captures one frame, sets the instruction from the spot, and queries miners for one action. Two scorer modes exist, selected by SCORER_MODE:

ModeScoring of one miner response
hash (default, described in the code as a local beta proxy)0.10 for parseable output; plus 0.20 if the action id is in the allowed set; plus 0.60 if it equals the action expected from a keyword heuristic on the instruction (stop, left, right, strafe, up, down, photo), otherwise plus 0.10; plus 0.10 times the miner's declared confidence. Scores are normalised across miners to sum to one and set as weights.
apiEach response is posted to an external scorer service (SCORER_API) and the returned score is used; on failure the response scores zero.

The AI verifier as documented

The documented AI verifier samples about six frames from the execution video (JPEG, width at most 640 pixels), sends them with the task instruction to a vision-capable LLM (gpt-4o-mini in the reference implementation) and requires strict JSON with six integer metrics on a 0 to 100 scale (accuracy, speed, safety, optimal_track, energy_efficiency, trajectory_stability), a holistic final_pct, a verdict of success, failure or inconclusive, and a one-paragraph reasoning. Multiple verifiers are emulated by calling the model three times with different frame subsets or perturbed prompts and taking a per-column average or an LLM consensus as the final row. Validators may substitute local models (an API-based LLM or a local Llama in the April 2026 answers); the on-chain record carries the signed score, not the model identity.
