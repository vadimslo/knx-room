3.8 Node and validator client repositories, release history, contributor list

Tier 2 Filed, partial

In preparation. Reviewer access to the private repositories under NDA; release tags; contributor list.

Four public repositories sit under github.com/konnex-world: the chain runtime (a Bittensor subtensor fork), the chain SDK (a Bittensor SDK fork), the drone-navigation subnet with its miner and validator stacks, and a robot gateway fork of OpenClaw. Active development, code review and CI run on a private GitLab; GitHub carries production-ready code after internal review, and reviewer access to the private repositories is offered under a mutual NDA. On the testnet the explorer shows 8 registered subnet validators and 257 registered miners across the three live subnets, while L1 block production remains with the two genesis validators operated by Konnex.

The GitHub contributor lists of the two chain repositories carry the upstream Bittensor history (72 listed contributors on the runtime fork, at least 100 on the SDK fork) and are not a measure of Konnex engineering headcount. Konnex-specific commits on GitHub are authored under the Chief Technology Officer's account, consistent with the stated model in which GitHub reflects release cycles rather than daily development. The SDK README links to the development GitLab at git.konnex.world.

The roboarm VLA and SLAM subnet code, the explorer, the control plane and the KNX token contract are not in the public repositories. The documentation site links to a GitHub organisation named konnex-network, which does not exist; the code is under konnex-world.

Private development and reviewer access

The node software is not fully open source: production-ready code is published to GitHub after internal review and testing, and active development with code review and CI runs on the private GitLab. Reviewer access to the private repositories is offered to counterparties under a mutual NDA on request. The node binary has no built-in automatic update mechanism; operators are expected to track releases with their own tooling.
